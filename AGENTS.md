This file is for AI coding agents (Claude Code, Codex and others) that help someone contribute to `mathcommunity/oai-math-revised`. Humans may find it useful too; the main guide is [README.md](README.md). Maintainers review every pull request; following these rules means your PR needs fewer changes.

## What this repository is

A community fork of [openai/math](https://github.com/openai/math): 721 manuscripts written by an OpenAI model, grouped into 373 result families (as of OpenAI's update of 2026-10-26). The community adds missing citations, corrects errors, records follow-up work and comments, and organizes reading groups. Nothing here is peer reviewed or verified, and nothing you write should suggest that it is (no claims that a paper or result is verified, correct or certified; no scores).

The website (https://mathcommunity.github.io/oai-math-revised/) is generated from the files in this repository by `site/build.py`, so the formats below matter: the site parses them.

## Layout

- `preprints/<paper>/` one folder per manuscript. **Never rename or move these folders**; links, citations and `lean/formalization.yaml` depend on the names.
  - `README.md` title, `**Author:**`, `**Date:**`, BibTeX citation, version notes.
  - the PDF (`paper.pdf`, `main.pdf`, ...) and the TeX sources in `build/`.
  - `NOTES.md` human-written notes (format below).
  - `AGENT_NOTES.md` AI-collected context, shown on the site as unreviewed. Generated by the maintainers' tools in `tools/agent_notes/`; format in [docs/AGENT_NOTES_FORMAT.md](docs/AGENT_NOTES_FORMAT.md). Do not add your own findings here; to correct an entry, say so in an issue or PR.
- `CONTENTS.md`, `overview.tex` OpenAI's catalogue (families, titles, abstracts). The site reads them; do not reformat them.
- `lean/` OpenAI's Lean formalizations. `lean/docs/<family>.md` describe their scope.
- `site/` the website generator (see [site/README.md](site/README.md)).
- The repository is large. To work on a few papers, use a sparse checkout: [docs/SPARSE_CHECKOUT.md](docs/SPARSE_CHECKOUT.md).

## Scope of changes to a manuscript

In scope: adding missing citations and related prior work, correcting attribution, fixing mathematical errors that can be fixed, correcting Lean statements that do not match the paper (in a separate pull request), and pointing to follow-up work or expositions (for example in an unnumbered remark). Rewriting sections for style, or replacing the manuscript with a new version, is currently out of scope; propose it in an issue first.

## Editing a manuscript

1. Edit the TeX in `preprints/<paper>/build/`. Keep theorem, section and equation numbering unchanged (use unnumbered remarks for additions).
2. Set the byline to `OpenAI (with community contributions)` and the date to the date of your change, in the TeX (`\author`, `\date`, `pdfauthor` if present) and in `README.md` (`**Author:**`, `**Date:**` and the BibTeX `author` field).
3. Recompile and replace the PDF, keeping its file name. Check that there are no undefined references or citations. Do not commit auxiliary files (`.aux`, `.log`, `.bbl`, ...).
4. Every reference you add must exist: check it at its DOI, arXiv, journal or publisher page, and make sure the bibliographic data (authors, title, year, venue) match. Never cite something only because a search tool or language model mentioned it.
5. Add a line under "Contributions" in the paper's `NOTES.md` (next section).
6. One paper (or one family) per pull request where possible. Fill in the pull request template.

## NOTES.md format

`NOTES.md` is written by people. If you draft entries, the contributor must check them; never paste text from `AGENT_NOTES.md` without checking the source. If the file does not exist, create it with these sections:

```
## Contributions

## Follow-up works

## Constructive comments / reviews

## People interested in meeting to work on digestion
```

- **Contributions**: one line per accepted change to the paper or its notes, newest at the bottom. The site shows these lines on the paper's page and under "Activity", so the format is strict:

  ```
  - 2026-10-20 @github-handle: What changed, in one or two sentences ([PR #3](https://github.com/mathcommunity/oai-math-revised/pull/3)).
  - 2026-10-21 @handle-one (Optional Name), @handle-two: ...
  ```

  Date `YYYY-MM-DD` (the day of the change, e.g. when the pull request was opened or merged), then one or more people separated by commas (a GitHub handle, optionally followed by a name in parentheses; a plain name for someone without a GitHub account), a colon and a space, and the description. Each entry must fit on one line. Sign-ups to "People interested" also get a line. If you do not know the PR number yet, leave the link out; a maintainer adds it. If AI tools were used substantially, say so in the description (for example "Drafted with Claude Code; sources checked by the contributor").
- **Follow-up works**, **Constructive comments / reviews**: one item per line with a link and one neutral sentence on how it relates to the paper. Reproduce other people's comments only with their permission.
- **People interested**: add only the contributor's own name, or names whose owners explicitly agreed.

## Issues instead of pull requests

For a report without a fix, use the issue forms (`.github/ISSUE_TEMPLATE/`): problem, reference or comment, interest. Each asks for the paper's folder name. The paper pages on the website have buttons that open them pre-filled.

For open-ended discussion of a paper (questions, explanations, reading notes) there is one GitHub Discussion per paper in the "Papers" category, created from the form `.github/DISCUSSION_TEMPLATE/papers.yml` (it asks for the folder name). Before starting one, check the paper's page on the website: if a discussion exists, its button links to it; post there instead of opening a second one.

## Disclosure and conduct

- State in the pull request description which tools were used and what the human contributor checked.
- Do not invent names, quotes, references or results. Do not add personal information beyond public names.
- Do not change other papers, the catalogue, the Lean library or the site in a paper PR.

## Checking your change

The site build parses `README.md` and `NOTES.md`, so run it when you change them:

```sh
pip install jinja2 markdown nh3
python3 site/build.py --pdfs none --out /tmp/site
```

It prints a warning for any "Contributions" line it cannot read. Open `/tmp/site/papers/<paper>/index.html` to see the paper page.
